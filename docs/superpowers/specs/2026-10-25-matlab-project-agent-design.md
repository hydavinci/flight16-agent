## 1. 产品目标与已确认边界

用户输入工程目录、工程分析要求、评价指标，Agent 理解需求、发现已有工程入口、
提出可核对的计划，获得确认后调用本机 MATLAB，最终给出有实际证据的结论报告。
截图中的 D1-1 是验收案例，而不是 Agent 核心中的业务分支。

用户已选择以下边界：

- 工程提供者保证模型和已有初始化、分析入口本身可运行。
- Agent 识别并调用已有入口；缺少必要配置或分析脚本时向用户澄清。
- 不生成分析脚本，不修改原模型，不自动补建激励、日志或控制器。
- 已由工程明确提供的设置应直接沿用，不要求用户重复填写。
- 保留既有基线确认、严格能力契约、不可变证据、恢复及历史兼容机制。

本次的通用性包含工程目录发现、任务编排、参数化计算和确定性评价，
不承诺支持没有相应工具的任意算法。首批可组合工具覆盖：
执行已有工程入口或 Simulink 模型、导出指定时序、调用 stepinfo、评价及交付。
已有其他注册能力继续可用，不把所有工程任务强制转成阶跃分析。

## 3. 用户交互与输入来源

### 3.1 三项输入

工程流程提供：

1. 工程目录：默认明确指向本机 MATLAB 工程资源，而非猜测 Worker 主机。
2. 工程分析要求：描述执行方法、已有入口、工况及所需输出。
3. 评价指标：可选；验证任务需要明确判据，纯分析允许不填。

成果目录仍为可选项。知识问答不因增加工程字段而强制要求目录。
旧的单消息 API 和已有会话继续兼容；新增独立字段不改变原消息的含义。
结构化字段进入服务端保存的原始用户消息，保留字段标签与原文，
使每条阈值和分析参数仍能引用用户实际提交的文字，而非模型重述。
若同时提交两套相互冲突的需求字段，返回明确错误，不静默覆盖。

### 3.2 发现与澄清

专用 `flight-agent.project.json` 可继续作为已有明确配置使用，但不再是新工程的前提。
普通工程可以通过已有文件、工程说明和用户确认的入口绑定接入。

对于多个模型、多个初始化入口、必需参数不明或信号身份有歧义的情况，
Agent 列出候选与依据并向用户澄清，不按文件名相似度直接执行。
澄清结果进入会话，下次规划沿用，不要求用户编辑专用 JSON 才能继续。
用户明确且无歧义的后续更正仅替代对应计算设置的旧用户声明；
原消息、判据引用及基线历史全部保留，无关后续消息不清除已有选择。

激励幅值、时刻、仿真时长和采样等已有工程设置，沿用工程配置并在执行时记录。
只有真实缺项、冲突或不支持的设置变更才要求补充。
不能把“尚未运行才能观察到的设置”一律认定为用户缺失输入。

## 4. 工程发现与资源契约

新增独立的本机工程描述，不扩展旧 `ProjectDescriptor` 的固定分析枚举来冒充通用性。
描述至少包含：

- 资源所属主机、工程根目录、文件清单与整体指纹。
- 已发现的 `.prj`、`.slx`、`.mdl`、`.m` 文件及可引用的工程说明。
- 初始化、仿真和已有分析入口候选；每个候选记录相对路径、类型及发现依据。
- 工程已明确给出的依赖、输入响应信号、输出位置和可用工况。
- 未解析项和冲突，不把未证实的猜测写成已知事实。

发现阶段只读取受限的本地文件和静态元数据：
不启动 MATLAB，不运行 `.m`，不打开 MATLAB 工程，不调用 `load_system`。
这些操作可能执行工程回调，均属于用户确认后的工程执行。
对 `.slx` 的静态解析不得自动解压到源工程，不执行其中内容。

文件内容仅作为工程数据，不能覆盖规划器约束或授予工具执行权限。
沿用工程文件数、总大小、路径、符号链接和输出目录分离检查。
源工程外的依赖不被静默扫描；要求工程提供者说明并完成可快照的准备。

资源 `matlab_project` 明确位于 Agent 主机，使用本地目录浏览器。
原 `simulink_project` / Worker 与诊断资源的位置和历史引用不变。
本机 MATLAB Engine 不可用时仍允许静态发现，但执行能力必须明确不可用。

## 5. 可组合能力与数据流

### 5.1 执行已有入口

新增通用的本机工程执行能力，使用严格的结构化输入：

- 已确认资源绑定、工作目录、已有初始化入口及有限 JSON 参数。
- 执行已有分析脚本/函数，或对明确选定的已有 Simulink 模型调用仿真。
- 所需输出的显式字段路径、日志信号名及单位，不接受 MATLAB 表达式。
- 本次要求的工况标识及沿用工程设置的说明。

入口路径必须对应已发现、已确认工程副本中的文件。
工程说明或模型响应不能直接变成 MATLAB 代码。
调用由版本化的程序桥接实现，不生成 `.m` 分析脚本或拼接执行表达式。

MATLAB-only 工程可以执行已有分析入口并读取其输出；
Simulink 工程可以执行已有初始化入口后仿真。
已有分析入口模式仍必须保留用户、工程说明或显式配置指定的初始化入口；
未指定时允许纯分析入口独立运行，不把其他候选文件或分析入口本身强加为初始化。
两种方式都必须实际产生请求的时序或结果，不能仅凭入口正常返回就判定完成。
不支持的入口签名、输出类型和计算方法要明确报告缺口。

执行能力输出规范化时序文件、原始 MAT 数据、日志、实际设置及相应证据描述。
时序引用包括生产节点、相对文件名、摘要、大小、信号身份和单位。
数组与文件均采用有界输出，不把完整工程或无界数组放进模型上下文。

### 5.2 stepinfo 指标能力

新增独立的 stepinfo 能力，通过依赖绑定读取上一节点的已验证时序工件，
不接受模型自行填写的“实测数组”作为工程执行结果。
该能力在 MATLAB 中计算指标；既有 Python 评价器只比较实际指标，不代算或猜测。

输入包含实际输入/响应时序引用、调节带、指标计算所需的显式设置和有效性策略。
指标声明属于该能力，不属于 Agent 核心的全局固定枚举。
首批输出为超调量 `%` 与调节时间 `s`，并保留原始分析文件及曲线。

复用既有单阶跃识别、前后时序、稳态窗口、有限值及时间轴有效性检查，
但新路径中的信号名称、工况和调节带均不固化为 F-16、配平点 1 或 5%。
调节时间以实际识别的阶跃时刻为时间原点；参考初末值及有效性检查写入证据。
多次激励、无法对应的信号、不可靠稳态等情况保留无效证据和原因，
不得强行输出有效指标。

计算设置来源按“用户本次明确要求、已有工程明确设置、已公布的工具策略”核对；
来源冲突时澄清，不能静默选择。有效性策略不自动变成验收判据。
调节带及稳态策略逐字段解析有效用户声明与全部当前工程声明；
仅无用户/工程声明的稳态字段沿用已公布默认值。提案有效输入遗漏或不符时澄清，
用户更正不能覆盖仍有效的工程冲突；含糊、条件式或否定式更正不被猜测为新设置。

### 5.3 节点与 MATLAB 生命周期

首个验收案例的依赖图为：

```text
已有入口/模型执行 → 实测时序 → stepinfo 指标 → 判据评价 → 报告
```

初始化与仿真在执行节点的同一 MATLAB 生命周期中进行。
节点之间只通过可验证的序列化输出和工件传递数据，不依赖隐藏的共享 base workspace。
stepinfo 节点可以在独立的本机 MATLAB 生命周期读取已导出的时序。
首版不增加持久 MATLAB 会话池；避免把性能优化变成恢复正确性的前提。

每个节点仍消耗已确认预算。模型不能通过拆分操作、缓存或把计算写进描述来绕过预算。
执行能力、指标能力、评价能力和交付能力分别声明版本与权限。

## 6. 本机执行、恢复与历史兼容

本机后端直接启动专用 Python 子进程，由该子进程通过 MATLAB Engine 执行；
用户只需启动 Agent 服务，不需要再启动本机 HTTP Worker。
子进程使用工程快照，输出落入本次运行目录，不写回源工程。

允许部署时指定兼容 MATLAB Engine 的本机 Python 解释器，
使 Web 与 MATLAB 不必使用同一虚拟环境。该解释器须已安装项目及匹配的 Engine；
缺失时明确报告，不自动安装。可用性检查使用有界子进程探测包与入口，
不启动 Engine，也不能仅检查 Web 解释器就认定本机 MATLAB 不可用。

执行前再次检查资源、入口和能力快照；源文件改变必须重新规划并确认。
记录原始调用 ID、请求摘要、运行状态、日志和最终回执；
保留超时、输出大小及自有进程清理机制，不终止用户其他 MATLAB 会话。
不自动安装依赖、修改系统工具链或修复模型。

恢复仅核对原本机运行 ID、已持久化状态和回执。
不能因为服务重启、网络调用失败或某个 PID 不存在就推断仿真成功。
没有可验证终态时停止为未知执行状态，不能自动重发；
已知失败仍要求显式重试，沿用当前区分 resume / retry 的原则。

旧 Worker、旧 Simulink 能力和历史任务继续使用原来的契约与恢复入口。
旧阶跃指标调用未传新参数时保持现有 5% 行为，不能改变已有回执含义。
新能力使用独立名称和快照，不让旧基线静默获得更广执行范围。
远程执行保留为明确选择的选项，而不是本机用户的必需部署条件。

## 7. 评价、报告与首个验收案例

用户给定的示例输入：

| 输入 | 内容 |
| --- | --- |
| 工程 | 提供者已准备并人工核验的 MATLAB / Simulink 工程目录 |
| 分析要求 | Stick 阶跃激励；非线性闭环时域仿真；stepinfo 评价 |
| 评价指标 | 超调量 <=10%；调节时间 <=3 s，调节带为 5% |

这里的 5% 是指标计算参数，10% 和 3 s 是验收阈值，三者不得混淆。
计划显示实际选择的初始化/执行入口、信号、工况来源、计算参数、判据及交付物。
不自动追加开环分析、其他指标或整机安全结论。

报告至少包括：

- 原始分析需求、评价基线与来源。
- 实际使用的工程指纹、入口、MATLAB 信息、设置和执行状态。
- 响应曲线、阶跃及参考值说明、实际指标、单位、阈值和逐项结论。
- 数值有效性、无法满足的需求、失败或无法判定的具体原因。
- 原始时序、MAT 数据、日志和不可变调用回执的证据索引。

采用现有确定性评价规则，不把显示四舍五入后的数字用于判定。
缺失、无效、歧义或单位不一致的证据不得判为通过。
报告区分执行完成、数值有效及判据通过。
“非线性闭环”等工程语义记录其工程提供者/配置来源，不因文件扩展名而自行认证。

本案例按用户要求交付 Word 结论报告和 JSON 证据索引；
其他任务仍按其实际交付要求执行，不强制所有知识回答或纯分析生成 Word。

## 8. 验证与验收标准

### 8.1 自动化软件验证

- 两套布局、模型名称、信号名称不同的准备工程，不增加专用业务分支。
- 没有专用登记文件时可以发现候选并形成计划；有歧义时先澄清。
- 静态发现和规划阶段 MATLAB 启动次数为零。
- 确认前零执行；错误版本、资源变更和能力快照不一致均拒绝执行。
- 执行已有 MATLAB 入口和 Simulink 模型两条路径均有覆盖。
- 节点间时序来源、摘要、单位和生产者必须验证，篡改与伪造输入被拒绝。
- 5% 调节带进入实际计算参数；另一个显式调节带不需修改 Agent 核心。
- 10% 与 3 s 的边界比较、无效稳态、多阶跃、缺日志和运行失败有回归覆盖。
- 本机运行恢复、未知状态不重发、已知失败显式重试有覆盖。
- Web 三项输入、澄清、确认、结果与 Word/JSON 下载有 HTTP 和浏览器测试。
- 现有 Worker、离线诊断、旧任务历史与上传工作台测试保持通过。

### 8.2 真实 MATLAB 验证

使用已安装并许可、Engine 兼容的本机 MATLAB，显式运行可选真实集成测试：
覆盖真实已有入口执行、实际 Simulink 仿真、stepinfo、判据比较及报告下载。
合成测试工程只能证明工具链可运行，不替代真实用户工程的业务验收。

真实用户工程必须由用户明确提供目录、必要的已有入口和人工参考结果；
不得自行扫描工作区外工程，也不得把测试替身输出写成真实 MATLAB 证据。
按双方确认的独立数值参考与容差验收；未提供或未运行时明确记录未验证。
真实模型服务的结构化规划需要单独进行端到端联调，离线模型替身测试不代替它。

## 9. 实施顺序与非目标

书面设计获确认后，再编写逐步实施计划，并按以下依赖推进：

1. 静态工程发现、独立资源契约和澄清回填。
2. 本机执行后端、已有入口调用、规范化时序和恢复回执。
3. 可组合 stepinfo 能力与显式计算参数，接入现有评价和交付。
4. 规划上下文、Web/CLI 输入与本机资源默认值。
5. 回归、可选真实集成与直接相关用户文档。

不包含自动生成脚本、自动配平、模型编辑、控制器优化、参数搜索、
自动故障修复、多用户平台、任务队列扩容或任意插件动态加载。
新增计算方法通过严格注册能力扩展，不通过放开任意代码执行实现。
