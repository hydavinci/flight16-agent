# 通用工程 Agent：需求驱动与注册能力设计

日期：2026-10-21

状态：本文及实施计划已获用户审阅通过；已授权在当前工作区实施，保留已有修改，不提交。

设计与计划阶段仅编写文档；实施阶段不提交、不重启现有服务，
不改动既有外部工程或运行记录。

## 1. 目标与范围

保留现有“目录与自然语言输入、确认后执行、展示证据与交付物”的使用方式，
将产品从 Demo 驱动改为需求驱动。新任务不要求用户选择 D1/D2，
也不以这两个名称作为核心任务类型。

通用性的边界是：Agent 能理解需求，组合已注册且可用的计算工具；
遇到能力缺口时明确说明，接入相应工具后才能执行。
“通用”不表示现有计算工具已经支持所有模型、工况或算法。

本次改造包括统一任务契约、判据来源、能力目录、执行与展示，以及历史兼容。
不包括生成或执行任意 MATLAB/Python 脚本、自动安装工具、修改源工程、
控制器优化、候选方案采纳、插件市场或热加载。

## 2. 现有基础与必须解除的耦合

复用以下已有机制，而不是重写整个系统：

- `runtime/capabilities.py` 的严格输入输出契约、版本、注册与权限检查。
- `runtime/tasks.py` 的依赖图校验，以及 `runtime/loop.py` 的有界执行驱动。
- 执行回执、输入与输出指纹、交付物校验、确认、持久化和恢复机制。
- 当前 API 模型后端和未提交的 Copilot CLI 后端，不增加新的模型服务。

以下限制必须退出新任务的核心契约：

| 当前耦合 | 目标归属 |
| --- | --- |
| `Scenario` 中的 `d1`、`d2` 与页面选择器 | 仅限历史兼容，不参与新任务分类 |
| 固定的两种分析与四个指标 | 具体能力的元数据与输出契约 |
| Demo 阈值与要求指标完整覆盖的规则 | 用户需求、明确采纳的标准与任务判据 |
| 配平点 1、F16 文件布局、Simulink 初始化约定 | 工程适配器 |
| 所有通用任务必需的 controller/plant 设计引用 | 按能力要求提供的资源引用 |
| 验证任务固定的分析、评价、交付节点结构 | 需求驱动的能力依赖图 |

现有文档 `docs/d1-agent.md`、`docs/d2-agent.md` 描述的是当前行为，
不是本文目标已经实现的证明。实施时应同步更新相关说明。

## 3. 用户交互

主界面保留工程/数据目录、任务需求、成果目录和对话，移除 D1/D2 选择器。
目录不是所有任务的必填项；知识问答不要求目录或 MATLAB。

目录必须标明所属主机。工程目录可位于 Worker，离线数据可位于 Web 主机；
不能因为用户未选择任务类型，就把同一路径静默解释为另一台主机的路径。
目录位置无法确定时澄清；现有本机原生选择器的拓扑与授权限制保持不变。

Agent 根据需求、已授权读取的资源和能力目录，作出回答、澄清或提出执行方案。
确认卡片使用“执行方案”语言，内部仍保存版本化基线，展示：
目标、输入版本、工况、工具及版本、计算有效性策略、验收判据及来源、
权限、预算和成果目录。不让用户从 D1/D2 名称推断这些信息。

两类需求应有不同结果：

- “分析响应曲线并给出指标”：允许没有验收判据，交付数值、有效性和解释，
  不生成整体 PASS/FAIL，也不把“未要求评价”显示为“不确定是否合格”。
- “验证响应是否合格”：若缺少必要判据，先询问标准；不补入 Demo 默认值。
  用户只要求检验一个指标时，不强迫其补齐同一工具的其他输出指标。

用户主动要求采用某示例标准时，可以提出对应判据，
但必须注明示例来源和适用范围并获得确认，不能宣称它是正式工程标准。

## 4. 统一任务契约

以下为拟议契约，不表示这些类型已经存在。
首版新任务使用独立的 `schema_version = "2.0"`，旧任务继续按原契约解码。

| 对象 | 最小内容与约束 |
| --- | --- |
| TaskRequest | 原始需求、消息引用、可选目录/资源引用、成果目录 |
| TaskRequirements | 目标、分析或验证意图、所需输出、适用工况、判据、交付要求 |
| ResourceReference | 资源 ID、类型、所属主机、受限定位信息、版本/指纹及来源 |
| Criterion | 唯一 ID、生产节点与指标引用、比较符、阈值、单位、工况引用、来源引用 |
| TaskBaseline | 需求、资源指纹、能力与版本、节点与输入、权限、预算、判定策略及确认记录 |
| TaskResult | 执行状态、观测结果、可选评价、证据引用、交付物与未满足需求 |

资源类型与角色由适配器声明。没有 controller/plant 的数据分析任务不得虚构
这两个对象或使用占位指纹；需要它们的能力仍须验证真实引用。
沿用旧设计引用的任务不能因新契约出现而失去原来的约束。
资源解析继续执行路径穿越、符号链接、源目录与成果目录分离，
以及现有文件数和大小限制，不能因采用通用引用而跳过检查。

同一能力在不同工况运行时，判据绑定具体生产节点、指标和工况，
不能只凭一个指标名匹配任意结果。节点间数据依赖使用受校验的输出引用，
只允许引用已声明的祖先节点及其契约字段，不使用表达式求值或拼接代码。

所有提案都须经过确定性校验，不能仅靠提示词保证需求完整、
能力存在、引用合法或权限一致。模型输出不合法时显示具体错误，不回退到 Demo。

## 5. 判据、有效性与评价

### 5.1 判据来源

每条验收判据都必须可追溯到用户消息，或用户明确采纳的已提供标准/示例。
来源记录包括引用位置；文件标准还包括文件指纹，
版本名称只有在来源实际提供时才记录，不能由 LLM 编造。

“使用标准”但未说明采用哪个版本，或标准与工程工况冲突时，先澄清。
LLM 可以抽取和组织判据，不能自行决定工程阈值。

首版内置标量评价支持 `<`、`<=`、`==`、`>=`、`>`；
区间用绑定同一结果的上下界判据表示。比较使用实际数值，不先按显示精度取整，
不隐含浮点容差。容差须明确为区间或由专门评价能力声明。
复杂规则须由已注册评价能力实现；不支持的规则报告能力缺口。

指标 ID 和单位来自能力声明，不是核心中的固定枚举。
直接比较要求单位一致；单位换算只能由已注册且版本化的转换能力完成，
不能由 LLM 心算或仅修改单位标签。

### 5.2 计算有效性不是验收标准

稳态筛查、采样充分性、线性化约定等属于工具的计算有效性策略。
它们应有版本、适用条件和依据，并在确认信息与证据中可见，
但不能与“超调不超过多少”等业务标准混为一谈。

适配器可以有明确声明的数值质量默认策略；不得把这种机制用于注入验收阈值。
无效数值不能参与合格比较，不能用零、空数组或 LLM 推测值代替。
无穷大或未定义等特殊值必须结构化记录，其可比性由工具契约规定。

### 5.3 结果分层

执行成功、数值有效、满足验收标准是三个独立维度。
一次计算完成不等于通过；一项判据失败也不能被总体文字说明掩盖。

对要求整体合格判定的任务，首版明确采用现有保守聚合策略：
任一必需判据缺少有效证据则为 `undetermined`；
否则任一失败为 `fail`；全部通过才为 `pass`。
这一策略在确认卡片中明示。即使整体为 `undetermined`，
仍须突出已经确定的失败项。

没有整体评价需求时不自动生成整体结论。
新任务不要求某个分析工具输出的每个指标都成为验收项。
需要其他聚合逻辑时，使用明确注册的评价能力，不能悄悄改变以上语义。

## 6. 能力插件与工程适配器

扩展现有能力注册机制。每项能力声明：
名称与版本、描述、严格输入输出 schema、所需资源与主机位置、
可产生的指标及单位、适用条件、数值质量策略、权限影响和可用性。
不可用的能力可以被展示，但必须附原因，不能被规划为可执行节点。

核心只理解通用契约和注册目录，不维护 `step_response` 等封闭分析枚举。
计算、评价和交付都是可组合能力；不是每个任务都必须有这三类节点。

注册边界为受信任的启动装配清单。新增工具可以增加插件模块、测试及注册项，
不得要求修改核心编排、API 路由、通用页面或核心指标列表。
注册清单不是用户需求的一部分；LLM 不能指定模块导入、下载插件或执行动态代码。
插件加载失败、重名或契约错误应显式报错，不能静默忽略。

插件是受信任的已安装代码，权限检查不等于操作系统沙箱。
项目执行继续使用现有的显式同意、隔离副本和受控 Worker；
新注册不得绕过目录边界、Worker 认证或执行授权。
首版不开放候选写入和采纳权限，也不把项目写入包装成只读能力。

已有功能的接入方式：

- Simulink 适配器负责工程发现、初始化、信号、配平、原生模块与 MATLAB 调用；
  F16 配置是其一个显式工程配置，不成为其他插件的默认配置。
- 当前阶跃响应与裕度计算输出通用观测结构，保留原始算法与证据。
- 离线诊断作为注册能力接入，保留原有数据约束、诊断不确定性和有界内部流程。
- 评价与报告使用通用结果，不再只接受四个指标或固定 Demo 模板。

现有 F16 适配器仍可仅支持配平点 1。
请求其他配平点时必须说明该工具的限制，不能把任务改成配平点 1 再执行。
本次不承诺新增数值算法或扩大现有适配器的真实计算范围。
验收使用的第三种能力是最小测试插件，用于证明注册和组合边界，
不作为新增的正式工程计算产品交付。

## 7. 规划、执行与能力缺口

```text
需求 + 可选资源
  -> 理解需求 / 受控发现 / 查询能力目录
  -> 回答、澄清、能力缺口，或提出版本化方案
  -> 确定性校验 -> 用户确认
  -> 执行就绪节点 -> 保存回执与观测
  -> 继续、澄清/修订方案，或完成
  -> 结构化结果 + 证据 + 交付物 + 基于证据的解释
```

首版确认范围绑定具体能力版本、节点、输入、资源、权限与预算。
观察结果可用于选择已确认的就绪节点，不能借“自适应”扩大计算范围。
需要新增节点、修改参数/工况、替换资源或增加权限时，
提出新方案版本并重新确认；已注册适配器内部流程也不得超出其声明的边界。

保留回合数、调用次数、耗时和无进展限制。只有新增有效证据或完成需求相关节点
才算执行进展，重复解释不是进展。预算耗尽时停止后续派发并说明未完成项。
已派发但状态不明的调用先对账，不能因超时而重复派发。

能力缺口以结构化信息保存：未满足的需求、缺少的能力或输入、
现有工具限制，以及可行的下一步。不能将“不支持”改写成执行成功。
部分需求可执行时，可以提出明确标记为不完整的子方案，
经用户确认后执行；不能自行删除无法完成的验证要求。

工具失败显示错误与保留的证据，不自动换工具、换工程、降低质量策略或放宽标准。
未知执行状态继续阻止重试、重规划和任务切换，直至原调用完成对账。

## 8. 证据、复用与展示

数值结果由实际计算工具产生，判据由确定性评价能力比较，
LLM 仅组织需求、提出方案并解释已记录证据，不能更改计算或评价结果。

计算身份至少绑定能力版本、实际输入、资源指纹、工况、数值设置和依赖输出指纹。
验收判据、来源、聚合策略和交付要求绑定任务基线。
数据或工程变化不能复用旧计算；仅阈值变化时可以在新基线确认后
复用身份一致且通过校验的计算证据，再重新评价，不能改写旧结论。

每个观测包含生产节点、指标 ID、显示名称、值/特殊值、单位、
有效性与原因、工况和证据引用。其他输出可为契约声明的表格、
结构化发现或交付物；不强迫诊断结论伪装成数值指标。
页面按这些通用结构展示，新指标不需要新增 JavaScript 分支。

保留原始输出与回执指纹，以及文件的路径、大小和摘要。
执行失败、数值无效、判据失败、能力缺口、未要求评价应清晰区分。
不因输出缺少某种 Demo 图表或 Word 模板就认定通用任务失败；
但用户明确要求而缺失的交付物必须列为未满足需求。

## 9. 历史与接口兼容

新请求不需要 `scenario`；新界面不发送 D1/D2 选择。
旧请求中的 `scenario` 只通过显式兼容层翻译，
不能用它为新任务注入旧阈值或规避新确认机制。

旧任务按原始 schema 保存。兼容层把旧记录投影成通用展示结构，
不批量重写历史判据、指纹、确认时间、执行 ID 或报告。
旧 D1/D2 标识只能存在于兼容解码、适配器和既有记录中，
不能作为新任务的核心路由分支。

已确认或正在执行的旧任务按原版本与原授权恢复；
原能力不可用时显式阻止恢复，不自动升级工具版本。
旧的未确认任务不自动变成已确认的新任务；用户可以取消，
或按新契约重新提出方案，原记录继续保留。

在旧会话中提出新需求时，建立新版本并归档原任务。
原调用状态不明时仍先对账，不能通过归档或迁移解除限制。
保留现有上传工作台和 CLI 行为，不将其作为通用化重写的附带范围。

## 10. 验收条件

以下是实施完成的必要条件，不是当前已通过的测试。
模拟后端只证明编排正确；只有真实工具运行才可声称真实计算成功。

| 场景 | 必须验证的结果 |
| --- | --- |
| 新建任务 | 页面无 D1/D2 选择；API 不要求任务场景字段 |
| 无目录知识问答 | 可回答，不发现工程、不调用 MATLAB、不要求执行确认 |
| 只有分析需求 | 输出指标与证据，评价为空且明确为未要求，不生成整体 PASS/FAIL |
| 验证需求没有阈值 | 澄清，无隐含的 10%、3 秒、0 dB、0 度，无计算派发 |
| 用户给出自定义标准 | 提案、确认、评价和报告保留其原值、单位、工况与来源 |
| 只检验单一指标 | 不因工具还会输出其他指标而强迫补齐判据 |
| 同一指标不同工况 | 判据只匹配指定生产节点与工况，不能串用结果 |
| 第三种非 Demo 能力 | 仅增加插件及注册项即可规划、确认、执行和展示，无核心/路由/页面改动 |
| 第三种能力的组合 | 测试插件提供离线 RMSE 计算，与通用标量评价和交付组合；新单位与指标无需改核心枚举 |
| 非 F16 资源任务 | 不要求 F16 布局、配平点或虚构 controller/plant |
| 不支持的算法或工况 | 输出能力缺口；不生成脚本、不回退 Demo、不静默替换工况 |
| 单位或标准不明确 | 确认前澄清；不由 LLM 隐式换算或编造标准版本 |
| 无效必需证据且有失败项 | 整体为 undetermined，已确定的失败仍清晰展示 |
| 工程、输入或能力版本变化 | 原确认不再授权新计算；重新提出方案 |
| 仅验收阈值变化 | 新基线下重新评价，原证据和旧结论不被改写 |
| 未确认、越权或路径越界 | 执行被拒绝，无成功形状的替代结果 |
| 超时、无进展或预算耗尽 | 有界停止、记录原因；未知调用不重复派发 |
| 历史任务恢复 | 原版本、确认、执行 ID、证据与归档关系保持一致 |
| API 与 Copilot CLI 模型后端 | 都遵守同一新契约；非法提案不触发计算 |

真实 MATLAB 回归与工程执行须另行获得用户授权；
不得为了通过验收擅自修改工程或启动真实分析。

## 11. 实施顺序与完成边界

本文审阅通过后再编写具体实施计划。建议依次：
定义新契约及兼容投影；扩展能力声明与注册边界；统一规划和有界执行；
接入已有适配器；迁移页面与报告；完成第三种能力及历史恢复的验收。
这些步骤不代表可以跳过逐项行为验证后一次性替换运行中的系统。

本次完成的定义是：新任务通过通用契约和注册能力运行，验收标准有来源，
新工具不要求修改核心编排或页面，旧数据与授权链仍可校验。
只删除选择器、只改提示词或只重命名 D1/D2 均不算完成。
